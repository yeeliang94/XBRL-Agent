# Rolled-forward mTool workbooks

A comparative filing may use a rolled-forward mTool workbook instead of extracting both periods from the source report. Choose **Use a rolled-forward mTool workbook** under **Prior-year figures** in Filing setup. Declare the workbook's units and upload it before extraction. Its current-year numeric inputs must be blank, and its units must match the filing setup. Existing current-year inputs are refused so stale values cannot survive outside the canonical facts. Automatic output scaling is not enabled. Confirm detected year and entity columns when the layout requires it; the confirmation is tied to the exact detected map.

The importer reads prior-year numeric inputs through the existing taxonomy-address resolver. This includes the primary statements and selected structured numeric notes, including share-capital and related-party categories where the workbook has a prior-year section. Native mTool share-capital and related-party sheets file current-year figures only, so they normally contribute no prior-year inputs; numeric-note comparatives then remain absent rather than extracted. Note categories are read from mTool's category header rows; a sheet without them yields uncategorised values. Company and Group figures remain separate. Workbook formula totals remain derived. Subtotals that mTool stores as typed inputs, such as SOCIE other reserves, are preserved as authoritative canonical aggregates (`children_status=aggregate_only`) and counted as `aggregate_inputs`. Their amounts remain available for comparative review even when the component breakdown is absent. Available imported components that disagree with a typed subtotal create a review conflict; neither side is overwritten. Typed subtotals receive the same replacement and output-preservation checks as ordinary inputs. Explicit zero is retained; a blank input is not an observed zero.

The workbook ID and any column confirmation are saved with the draft and run configuration. The original file is retained under the session directory with a content hash, and redo copies it to the new session. Import revalidates the resolved statement formats, filing standard, entity level, dates when available and units before any extraction starts. Missing or unverified coverage is reported. Company identity still requires operator verification.

Agents receive a statement-specific list of imported values and field identities as historical data. They extract current-year figures from the current report and may choose new fields. The `check_prior_year` tool compares available PDF comparatives against exact imported concepts, entity scopes and categories. Differences remain visible; the tool never replaces imported figures. Unchecked comparatives remain unassessed. Narrative notes continue to reflect the current report; numeric tables inside narrative notes are not independently imported as structured facts.

Imported inputs enter the canonical fact store as `source='prior_year_workbook'`, with the workbook hash, worksheet and cell in their evidence and an import event in the fact journal. Extraction and reviewer writes to PY are refused in this mode, including category reassignment. Retry cleanup retains imported inputs and comparative assessments. Seeded comparatives do not count as extraction writes; a numeric-note agent that writes nothing still fails the normal completion guard. Review shows imported prior-year values as read-only in both Figures and numeric Notes. Existing statement and notes checks use the combined current-year and prior-year canonical data. Partial imported inputs can therefore expose prior-year imbalances rather than producing a false clean result.

Prepare mTool draft reuses the saved workbook. Only CY numeric writes are emitted, including matrix/movement destinations identified by period rather than by Excel column. Narrative notes and report fields retain their normal preparation workflow. A replacement workbook must contain the same imported prior-year inputs. Before releasing the output, the route verifies that the imported input values and cells' XML are unchanged and records the preservation count in the durable fill receipt. mTool Validate & Generate remains a native acceptance step.

Comparative findings are recalculated on manual rechecks as well as automatic checks. A failed assessment remains a visible warning.

Behavior is pinned by `tests/test_prior_year_workbook.py`, the human-file ingestion tests, and the Filing setup and Notes review frontend tests.
